## Part A — 하늘에 뜬 거대 가발

### A0. 증상

최대 줌아웃(글로브) 화면에서 하늘에 거대한 헤어 메시(번 헤어 모양, 회색·갈색)가 떠 있다. 사용자 스크린샷 기준 지구 반경의 1/3쯤 되는 크기이다.

### A1. 원인 가설 (설계자가 오프라인으로 확인함)

- `src/world/wear.rs`는 `Hair`(hair-*, brows-*)와 `Beard3d` 슬롯을 `needs_anchor() == false`로 두고 qchar `Head` 본에 **직속** 부착한다.
- 코드 주석은 "자체 아마추어(Armature ×0.01)가 상쇄"라고 하지만, **실제 GLB의 `Armature` 노드에는 scale이 없다(=1)**. 확인 파일은 `assets/models/qubase/hair-buns.glb`, `brows-regular.glb`이다.
- `Head` 본 월드 스케일이 ×100(`CharacterArmature`)이다. 그래서 헤어 스킨 조인트 체인(root→pelvis→…→Head, 높이 ~1.6)이 ×85 확대되고, 메시가 주민 위 수십~백 m 상공에 그려진다. 이것이 bigmesh가 보고한 `joint_spread 415m`와 헤어 extent 34~114m의 정체로 추정된다.

### A2. 확인 (배포 없이 먼저)

1. `assets/models/qubase/*.glb` 8종 전부에 대해 python으로 노드 스케일·스킨 조인트 루트를 덤프한다. Armature 스케일이 1인지, 스킨 조인트 체인 높이가 얼마인지 표로 남긴다.
2. qchar 본체 GLB에 자체 헤어·눈썹 메시가 있는지 확인한다(노드·메시 이름 덤프). 본체에 이미 헤어가 있으면 wear 헤어는 중복일 수 있으므로 **보고에 반드시 적는다**.
3. 배포가 필요하면 기존 `?tfdbg=bigmesh`(`tools/e2e/bigmesh.cjs`)로 `wear-hair-*`·`wear-brows-*` 메시의 월드 AABB와 조인트 분포를 수정 **전** 기준치로 기록한다.

### A3. 수정

1. `WearSlot::needs_anchor()`가 **모든 슬롯에서 true**가 되게 한다. Hair·Beard3d도 `ToolAnchor{actor}` 앵커 아래에 둔다. 스킨 메시는 조인트 GT로 그려지는데, 조인트가 wear 씬 하위이므로 앵커 상쇄가 그대로 적용된다.
2. 잘못된 주석(Armature ×0.01 상쇄)을 사실대로 고친다.
3. `offset()`·`scale()`의 Hair·Beard3d 값은 **일단 그대로** 둔다. 근거는 수염·안경이 앵커 이전 값 그대로 정상 위치에 앉았다는 점이다. A4 근접 컷에서 어긋남이 보일 때만 보정한다. 보정할 때는 픽셀 실측값을 근거로 남긴다.
4. 같은 슬롯 여러 아이템은 앵커를 공유한다(기존 로직). 헤어와 눈썹은 둘 다 `Hair` 슬롯이므로 앵커 하나를 공유한다.

### A4. 검증 (게이트 — 전부 통과해야 완료)

- **G-A1 (bigmesh)**: `bigmesh.cjs`에 판정을 추가한다. 모든 `wear-*` 하위 메시의 월드 AABB 최대 변이 **3 m 미만**이어야 하고, 스킨 조인트 분포도 3 m 미만이어야 한다. 수정 전 값과 수정 후 값을 같이 보고한다.
- **G-A2 (하늘 가발 픽셀)**: `tools/e2e/globe_artifact.cjs`에 모드 `W`를 추가한다.
  - 조건: 세로 412×732 @2.625, 최대 줌아웃, `?tfdbg=globe`.
  - 화면 상단 하늘 영역(HUD 바·미니맵·배지 박스 제외)에서 하늘 배경색과 ΔE가 큰 픽셀 수를 센다.
  - 수정 전 라이브에서 가발이 잡히는지 먼저 확인한다. 잡히지 않으면 헤어 강제 게이트(`wearbeard`처럼 `wearhair`)를 추가해서 결정적으로 재현한다.
  - 수정 후 3회 실행 모두 임계 미만이어야 한다.
- **G-A3 (근접 컷)**: `tools/e2e/wear_closeup.cjs`로 헤어 착용 주민을 근접 캡처한다. 헤어가 두피에 앉아야 한다(뜸·파묻힘·크기 이상이 없어야 함). 이미지를 직접 Read로 보고 판정 근거를 적는다. 안경 착용 주민 근접 컷도 함께 판정한다(이전 잔여 항목).
- **G-A4 (기존 게이트 회귀)**: `globe_artifact.cjs` base 모드 정확색 0, `root3d_globe`, `root3d_smoke`, `cargo test`를 통과해야 한다.

## Part B — 모바일 웹뷰 성능

목표는 세로 폰 웹뷰에서 프레임 시간을 줄이는 것이다. **룩(외형)은 바꾸지 않는다.** 측정 없는 최적화는 금지한다. 각 항목은 전후 수치로 입증한다.

### B1. 측정 도구 먼저 (Part A와 같은 배포에 실어도 됨)

1. `?tfdbg=perf` 게이트를 만든다(신규 `src/platform/perf_probe.rs` 또는 `src/world/perf_probe.rs`). 2초마다 `console.log("[perf] …")` 한 줄을 찍는다.
   - FPS, 프레임 시간 p50/p95(직전 2초 링버퍼)
   - 엔티티 수, 가시 메시 엔티티 수(`ViewVisibility` true), 스킨 메시 수, 잉크 헐 수
   - 의심 시스템의 누적 소요 ms. `web_time::Instant`(또는 wasm에서 쓸 수 있는 시계)로 감싼다. 대상은 `globe::apply_warp`, PreUpdate 재전파 블록(W2: restore_flat + propagate), 주민 FSM, 크레이트 leg_ik/tool_anchor_fit 앞뒤 구간 정도이다.
   - 게이트가 꺼져 있을 때는 비용 0이어야 한다(`run_if`).
2. `tools/e2e/perf.cjs`를 작성한다.
   - 세로 412×732 @2.625, Playwright headed.
   - CDP `Emulation.setCPUThrottlingRate(4)`로 모바일 CPU를 근사한다.
   - 세 장면에서 각각 15초씩 측정한다: 기본 줌, 최대 줌아웃(글로브), 근접 줌.
   - JS rAF 기반 FPS·프레임 간격 p50/p95와 `[perf]` 로그를 수집해 JSON으로 저장한다.
   - 장면당 2회 실행한다.
3. **수정 전 기준선**(현 라이브 v0.8.79 또는 B1만 들어간 첫 배포)을 표로 기록한다.

### B2. 후보 (측정 결과가 가리키는 것부터, 하나씩 적용하고 측정)

1. **렌더 해상도 상한**: 웹 DPR 2.625 그대로면 픽셀 수가 약 6.9배이다. 모바일(세로·터치)에서 렌더 스케일을 DPR ≤ 2.0으로 제한하는 방안을 검토한다.
   - bevy UI는 scale factor를 따르므로 HUD·미니맵·텍스트 크기와 레이아웃이 **변하지 않아야 한다**. `hud_baseline.cjs`, `menu_ui.cjs`로 확인한다.
   - UI 레이아웃이 깨지면 이 항목은 포기하고 보고한다.
2. **W2 재전파 비용**: PreUpdate에서 LastWarp가 Some일 때 매 프레임 전체 트리를 재전파한다. 측정상 비중이 크면 범위를 축소하는 방안을 낸다(예: 워프 대상 루트 하위만, 혹은 Changed 기반). **W2 계약(Update 구간 GT=평면)은 유지**하고, `root3d_globe`와 정확색 게이트로 회귀를 확인한다.
3. **글로브 줌아웃 시 원거리 비용 절감**: 줌아웃에서 주민이 몇 픽셀이 되는 구간을 대상으로 한다.
   - 잉크 헐 숨김(스킨 메시 드로 2배 제거)
   - 주민 애니메이션 갱신 빈도 낮춤 또는 정지
   - leg_ik 생략은 크레이트 소관이면 게임 쪽에서 컴포넌트 토글로만 처리한다.
   - 근접·기본 줌의 외형은 동일해야 한다.
4. **매 프레임 전수 순회 시스템**: perf 로그로 상위 시스템을 찾는다. 결과가 바뀌지 않는데 매 프레임 전체 쿼리를 도는 시스템은 Changed 필터나 주기 실행으로 바꾼다.
5. **진단 프로브 상시 비용**: map_audit, bigmesh, matcolor, toolprobe 등 모든 tfdbg 프로브가 게이트가 꺼져 있을 때 `run_if`로 완전히 빠지는지 확인하고, 아니면 고친다.

각 항목마다 "적용 전 → 후 p50/p95 (장면별)"을 기록한다. 개선이 측정 노이즈(±5%) 이하이면 되돌린다.

### B3. 검증 게이트

- **G-B1**: perf.cjs 기준 최대 줌아웃 또는 기본 줌의 p95 프레임 시간이 기준선보다 **유의하게(≥10%) 개선**되어야 한다. 개선이 없으면 없다고 정직하게 보고한다.
- **G-B2 (룩 불변)**: 기본 줌·근접 줌 스크린샷을 수정 전후로 비교한다. 해상도 상한을 적용하면 선명도 차이는 허용하지만 구도·색은 같아야 한다. `hud_baseline`, `root3d_smoke`, `root3d_globe`, globe_artifact base 0을 확인한다.
- **G-B3**: `cargo test`, `cargo clippy` 경고가 늘지 않아야 한다.
