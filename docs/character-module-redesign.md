# 캐릭터 시스템 재설계 — 접지·행동 모션·모듈화 (2026-10-24)

사용자 요청 3건을 하나의 설계로 통합:
1. "뒤꿈치 들림이 아직도 있다 — 캐릭터 설계 근본 문제를 확인 후 설계부터 개선"
2. "행동(사냥·물 떠 마시기·채집)마다 상황에 맞는 도구 사용 + 실제 동작 같은 모션 개선"
3. "다른 게임 개발 시 재활용할 수 있도록 모듈화"

## 1. 근본 문제 진단 (7+8차 보고까지의 누적 실측)

| # | 문제 | 지금까지의 치료 | 근본 원인 |
|---|---|---|---|
| 1 | 발이 지면에서 뜸/박힘 (4차~) | ground snap 단일 소유자(#104) | 측정 앵커(뼈) ≠ 시각 밑창 |
| 2 | 발 꺽임·늘어남 (5차) | PT 본 축소 추가 | **리그 구조**: Foot 본이 다리 체인과 분리(Root 직속), Idle 계열 클립에 Foot 채널 없음 |
| 3 | 뒷굽치 재부유 (6차) | _end 리프 본 앵커 | 밑창 메시의 31% 가중치가 정강이 본 — 포즈가 밑창을 끌고 다님 |
| 4 | 여전히 들림 (7차) | 가중치 리밸런스+SOLE_CLEAR+foot_lock(#113) | 위 치료로 메시 접지는 달성 |
| 5 | 여전히 들림 지각 (8차) | 블롭 그림자 매몰 복구(#115) | **접지 큐(그림자) 소실** — 눈은 그림자로 접지를 판단 |

**구조적 결론**: qchar 에셋(망가진 바인드 포즈·분리된 발 리그·채널 불완전 클립) 위에
치비화(런타임 뼈 스케일)·앵커 추정 접지·포즈 잠금을 3중으로 얹은 현재 설계는
패치가 패치를 낳는 구조다. 재사용 관점에서도 게임 의존(villager)과
게임 무관(리그·접지·모션)이 한 파일에 섞여 있다.

## 2. 목표 아키텍처 — `src/character/` (게임 무관 캐릭터 모듈)

platform(엔진 런타임) ↔ **character(캐릭터 프레임워크)** ↔ world(게임 콘텐츠) 3층.
character는 Bevy 플러그인으로 다른 게임에 그대로 복사 가능(= platform 계층 관례 동일).

```
src/character/
├─ mod.rs          CharacterPlugin — 마커 제네릭(C: CharacterTag) 구성
├─ rig.rs          리그 디스크립터: 본 이름 매핑 표(휴머노이드 표준 인터페이스),
│                  리그 캡처(바인드 포즈·앵커 위치), 리그 건전성 검사
│                  (발 채널 부재 클립 탐지 — 7차 사고의 자동 감지)
├─ proportion.rs   비율 시스템(치비화) — 뼈 스케일 대신 **오프라인 베이크 원칙**
│                  (수정 전: 런타임 스케일 → 스키닝·측정 부작용의 온상)
├─ ground.rs       접지 컨텍스트: 표면장 트레이트(SurfaceField) 주입,
│                  FootLift 측정(메시 밑창 기준 — 오프라인 δ 주입),
│                  접지 그림자(blob) 수명·위치
├─ leg_ik.rs       2본 IK(고관절→무릎→발목) + 발 플랜트(위치·수평 회전 고정).
│                  Idle/Interact 계열에서 클립 다리 스윙을 IK가 바로잡아
│                  밑창-정강이-발목 정합을 물리적으로 보장(7차 foot_lock의 완성형)
├─ action.rs       행동→모션 매핑 테이블(데이터 주도): activity 코드 →
│                  {클립, 루프/원샷, 도구 슬롯, 이벤트 타이밍(타격 프레임 등)}
├─ tool.rs         도구 시스템: 손 본 앵커 부착(wear 앵커 재사용) +
│                  상황 매칭(채집=낫·사냥=창·물=두레박 — 발명품 GLB 연동 §17.86)
└─ anim.rs         애님 상태 머신 래퍼(전환·속도·원샷 완료 콜백)
```

게임 측(world/villager.rs)은 `CharacterTag`, 표면장 구현, activity 코드만 제공.

## 3. 행동 모션 개선 (요청 #2)

qchar GLB가 이미 싣고 있는 미사용 클립 자산: Punch_L/R·Kick_L/R·Roll·
Hit_Receive·Death·Idle_Sword·Gun_Shoot 등(현재 4클립만 사용).
1단계(에셋 추가 없이): activity 매핑 확장 —
- `gather/fish` → Interact + 도구(낫·작살) 착용
- `hunt` → Punch/Kick 원샷 혼합(사냥 동작감) + 창
- `fetch_water/drink` → Interact 변형(물통 소품, 마시는 Idle 변주)
- `build` → Punch(망치) 교차 — 레거시 FE 'slash/hammer' 패리티
2단계: 부족 클립(마시기·줍기)은 assetgen 경로 또는 클립 믹싱(상반신
오버레이)으로 — 설계만 유보.
도구는 tool.rs 슬롯으로 — 발명품 model_url GLB가 우선, 없으면 기본 소품.

## 4. 이행 계획 (리스크 최소 순서)

1. **P0 (완료)**: 그림자 매몰 복구(#115) — 지각 원인 제거. 배포 후 사용자 확인.
2. **P1**: `src/character/` 골격 이식 — 기존 chibi.rs·ground.rs·foot_lock.rs·
   wear.rs 앵커 부분을 모듈로 이동(동작 보존 리팩터). 게이트: feet_check·smoke.
3. **P2**: leg_ik.rs — Idle 계열 다리 IK(foot_lock 대체·상위 호환).
4. **P3**: action.rs·tool.rs — 행동-도구 매핑 1단계(위 표).
5. **P4**: proportion 오프라인 베이크(신규 에셋 파이프라인 — assetgen 협의).

## 5. 주거 시설 포팅 (요청 #3 — 별도 트랙, 설계 완료)

레거시 FE 조사 완료(2026-10-24). 핵심 갭·결정 사항:
- **갭 1 — 시공 단계 뷰**: FE는 6단계 텍스처(부지→기둥→골조→벽→초벽→완성),
  3D는 완공 전까지 동일 발판. → 3단계 요약(부지·골조[기둥+보 메시]·벽체)로
  bld.rs에 스테이지 메시 추가 — res_sig에 stage 이미 있음.
- **갭 2 — '내 집' 표시**: owner===내 agentId 판정해 지붕 마커(올리브 깃발)+
  미니맵 핑. 인증 세션(tf-api /me)에서 agent id 취득.
- **갭 3 — 계약 문서**: §2.1 hut 행에 owner/ownerName/owners/builders,
  §3.1에 home kind 추가(3D는 이미 코드로 소비 중 — ../terrafolk 문서 보강).
- 진행률 무재스폰 경로 유지, 스테이지 전환 시에만 1회 재스폰 허용.

## 6. chartcraft 아키텍처 채택 (2026-10-24 벤치마크, ../chartcraft)

chartcraft(트레이딩 차트 엔진, 엔진 퍼스트 단일 코드베이스)에서 이식할 관행 —
채택 순서는 terrafolk 상황(라이브 관전 서비스)에 맞게 조정:

| # | 관행 | 이식 |
|---|---|---|
| 1 | **전 액션 커맨드 레지스트리**(CommandSpec 단일 dispatch) | 플레이어 행동(이동·채집·건설)을 world 커맨드 테이블로 — 입력·ws-link·테스트가 같은 경로 |
| 2 | **Session run 패닉 포착 + 스냅샷 롤백** | 서버 프레임 적용(apply.rs) 경계에 가드+롤백 — 절반 적용 상태 방지 |
| 3 | **cargo xtask layers 의존 방향 CI 강제** | platform↔world↔character 분리를 관례가 아니라 빌드 게이트로 |
| 4 | **디스플레이 리스트 + CPU 오라클 테스트** | world 상태→추상 이벤트/드로 리스트 분리로 헤드리스 검증(창 없는 회귀 게이트) |
| 5 | **hostile-params 퍼징 게이트** | ws-link 수신 메시지(적대적 입력) 전 커맨드 퍼징 — 세션 생존 CI |
| 6 | **버전 붙은 저장 포맷·필드별 관용 복원** | 서버 계약 파싱(unknown 키 무시·쓰레기 스킵·누락 유지) |
| 7 | **never-crash 린트 벨트**(이중) | 워크스페이스 unsafe forbid + 크레이트 루트 deny(unwrap/expect/panic) |
| 8 | **아크별 진행 블록·인시던트 로그·docs 검증 커밋** | 마일스톤마다 설계→구현→verified 커밋 리듬(본 docs/ 체계와 정합) |

1~2는 P2(커맨드화) 이행 시점에, 3·7은 저비용 즉시, 4~5는 E2E 하네스 성숙 후.

## 7. 재사용 원칙 (CLAUDE.md 반영 사항)

- `src/character/`는 게임 무관 — Bevy 프로젝트에 복사해 CharacterTag·표면장만
  구현하면 동작. 게임 고유(주민 AI·넷 동기)는 world/net에만 둔다.
- character 계층의 모든 상수(리그 이름·클립명·δ 오프셋)는 rig.rs 단일 표로.
- 검증 하네스(feet_check·footdbg·GLB 분석 스크립트)는 character 모듈 산하
  tools로 함께 이식 가능하게 유지.
